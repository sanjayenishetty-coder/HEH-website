# CLAUDE.md

Website + API for Hyderabad Entrepreneurs Hub (HEH). See README.md for structure, local run and deploy details.

## Key facts

- `web/` is the website and admin panel: React 18 + react-router, built with Vite (`npm run build` -> `web/dist`). `backend/` is a small Node/Express API on PostgreSQL. No other frameworks/UI libraries unless asked.
- `images/` (and `images/Website/`) hold the design screenshots; match them when changing layout or copy.
- Header and footer are in `web/src/components/Layout.jsx`; pages are in `web/src/pages/` and routed in `src/main.jsx`. A new page also needs its name in `src/pages.js` (the build writes `dist/<name>.html` because nginx uses `try_files $uri $uri.html`; no SPA fallback, no nginx change).
- Logo and favicon (from entrepreneurhub.in) are in `web/public/assets/brand/`: `logo.png` (transparent) for light backgrounds, `logo-light.png` (white text) for the navy footer. Core team photos (About page, entrepreneurhub.in/team) are in `public/assets/team/`; `public/` files are not hashed and are cached for a day, so a replaced photo gets a **new file name** plus a migration updating `members.photo_url` (see `0020`/`0021`).
- Naming on the public site differs from admin/portal on purpose: the About HEH menu item for `/our-members` is "Board Members", and that page shows the groups as Executive Council / Working Board / Advisory (`HEADING` in `pages/OurMembers.jsx`); `constants.js` and the admin/portal still say Working Committee / Advisory Board.
- Use the CSS variables in `:root` of `web/src/styles.css` for colours/fonts rather than new hex values.
- Pages must work at phone width. Breakpoints in `styles.css`: 1080px (tighter header), 960px (header button hidden, 4-up grids go 2-up), 860px (phone menu, single column), 520px (small phones). Check desktop at 1024px too, since the designs are 1024 wide.
- Icons: `<Icon name="..." />`; round badges `<Ic name="..." tone="blue" />` use the solid glyph from `FILLED` in `src/lib/icons.js` (matching the designs); add a solid version there when you add a badge icon.
- Built assets have hashed names, so no manual cache-busting is needed.
- Write `useEffect` bodies with braces (`useEffect(() => { window.scrollTo(0, 0); }, ...)`). A concise arrow returns its value, and React calls a non-function return as cleanup; `window.scrollTo` returns a Promise in current Chrome/Edge, which crashed every page change until a refresh.
- Dynamic content (events, members, stories) is managed in `/admin/`; `backend/src/seed.js` only holds sample content.
- Database changes go in a new `backend/migrations/NNNN_name.sql` (`npm run db:migrate:new -- name`), never by editing an applied migration (the runner checks checksums). Run `npm run db:migrate` locally and on the server.
- Admin login (`web/src/admin/Login.jsx`, designs in `images/Admin Login/.../Modified Login Page Designs`): accounts are in the `admin_users` table. The first one is created from `ADMIN_USER` + bcrypt `ADMIN_PASSWORD_HASH` + `ADMIN_EMAIL` in backend `.env` when the table is empty; after that the password lives in the DB ("Forgot Password?" emails a reset link; a reset signs out all sessions). Email features (reset, verify-email and `ADMIN_LOGIN_CODE=1` sign-in codes) need `SMTP_*`; Google sign-in needs `GOOGLE_CLIENT_ID`. Bcrypt hashes contain `$`, so never write the hash through an unquoted shell heredoc/variable (it gets mangled); write `.env` with node or a quoted heredoc. Login trims spaces; 10 failed tries per 15 min locks it. The local API uses the live DB through the SSH tunnel, so test sign-in changes against a throwaway DB, not the live one.
- Event approval (migration `0019`, `backend/src/eventapproval.js`): only **Working Committee** members add events (portal: Events > Add Event / My Event Submissions, `portal/EventSubmit.jsx`). They are saved unpublished with `approval_status = 'pending'` and appear on the website only after an **Executive Council** member (portal: Events > Event Approvals) or an admin (event editor > Approve & Publish, or Publish) approves them; a DB check makes `published` impossible unless approved. Member types come from Admin > Members > edit member (`core_team` = Executive Council, `working_committee`).
- Form option lists (industries, turnover ranges, enquiry types, story categories) live in `backend/src/constants.js` and are served by `GET /api/meta`.
- Member Portal at `/portal/` (designs: `images/Member Login Web Application/Part 1`): `web/src/portal/` (own bundle, hash routes like the admin), API `backend/src/routes/member.js` at `/api/member` (session cookie `heh_member`, `src/memberauth.js`). Members sign in with their email address once an admin turns on access in Admin > Members > edit member > "Member Portal access" (creates a temporary password shown once; `routes/portal-admin.js`). One sign-in screen serves everyone: `admin/Login.jsx` (styles `admin/login.css`) is one email + password form (no Member / Admin choice, no usernames or Membership IDs) shown only at `/login` (the header "Login" button; `pages/SignIn.jsx`). `/admin/` and `/portal/` send signed-out visitors, sign-outs, expired sessions and reset links there (`admin/toLogin.js`, `?for=admin|member&next=…`); it tries the member and admin logins and goes to the app of the account that matched. Admin accounts must have an email. Verification documents are stored outside the public uploads folder (`DOC_DIR`, default `<UPLOAD_DIR>-documents`) and only sent to the member and admins.

## Verifying changes

Build `web/` and run the API locally with `SERVE_STATIC=1` (serves `web/dist` on :1502), or run `npm run dev` in `web/` (port 5173, proxies `/api`). Test portal changes against the throwaway DB: turn on portal access for a test member in admin, sign in at `/portal/` (sign-in is rate limited to 10 per 15 min, so restart the local API between screenshot batches). Screenshot pages with headless Edge before reporting done (Edge enforces ~500px min window width; for phone width, render the page inside a 390px iframe served from the same origin, because the API sends `X-Frame-Options: SAMEORIGIN`):

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new --disable-gpu --hide-scrollbars --window-size=1600,900 --virtual-time-budget=5000 --screenshot=<scratchpad>\index.png "http://localhost:1502/"
```
